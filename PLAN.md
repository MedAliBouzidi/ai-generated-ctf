# VulnLab CTF - Project Plan & Specification

## 1. Project Overview
VulnLab CTF is a local educational cybersecurity practice lab consisting of 5 intentionally vulnerable web applications and 1 centralized scoreboard.

## 2. Port Allocations & Network Boundaries
All services bind strictly to `127.0.0.1` on the host to avoid exposing vulnerable containers to any external network or public interfaces.

| Service | Host Port | Container Port | Isolated Docker Network | Technology |
|---|---|---|---|---|
| **Scoreboard** | `127.0.0.1:8000` | `8000` | `vulnlab-scoreboard-net` | Python (FastAPI/SQLite/Tailwind CSS) |
| **blog-sqli** | `127.0.0.1:8001` | `8001` | `vulnlab-blog-net` | Python 3.12 (Flask + SQLite) |
| **notes-idor** | `127.0.0.1:8002` | `8002` | `vulnlab-notes-net` | Node.js 20 (Express + Postgres 16) |
| **file-share** | `127.0.0.1:8003` | `8003` | `vulnlab-files-net` | Python 3.12 (FastAPI) |
| **shop-auth** | `127.0.0.1:8004` | `8004` | `vulnlab-shop-net` | Node.js 20 (Express) |
| **ping-tool** | `127.0.0.1:8005` | `8005` | `vulnlab-ping-net` | Python 3.12 (Flask) |

> [!IMPORTANT]
> The scoreboard has **no network path** into any vulnerable app's internal container network. Each vulnerable app sits on its own distinct Docker bridge network.

## 3. Flag Format & Secret Management
- **Format**: `VULNLAB{<32_lowercase_hex_chars>}`.
- Every vulnerability at every difficulty has its own unique flag.
- Flags are generated by `scripts/gen-flags.sh` into `.env` (gitignored).
- Plaintext flags are **never** hardcoded into source code, Dockerfiles, images, or documentation.
- The scoreboard stores **only HMAC-SHA256 hashes** of the flags, keyed with `SCOREBOARD_SECRET`. Plaintext flags are never stored in the scoreboard database.
- Containers receive flags at runtime via environment variables passed by `docker-compose.yml`.

## 4. Difficulty Levels
Each app supports `easy`, `medium`, and `hard` modes via an environment variable (`DIFFICULTY` or `<APP>_DIFFICULTY`, defaulting to `easy`).
- **Easy (100 pts)**: Baseline vulnerability with minimal or no defense.
- **Medium (200 pts)**: Common partial defenses (e.g., naive regex blacklists, client-side checks, single-pass keyword stripping).
- **Hard (300 pts)**: Trickier bypasses (e.g., whitespace filters, alternate encodings, parameter pollution, second-order vectors).

## 5. Challenges Schema (`challenges.json`)
Every app root contains a `challenges.json` adhering to this JSON schema:

```json
[
  {
    "id": "blog-sqli-login-easy",
    "app": "blog-sqli",
    "title": "Blog SQLi - Admin Login Bypass (Easy)",
    "difficulty": "easy",
    "points": 100,
    "category": "SQL Injection",
    "owasp": "A03:2021-Injection",
    "description": "Bypass authentication on the blog login form without knowing the admin password.",
    "flag_env": "FLAG_BLOG_SQLI_LOGIN_EASY",
    "hints": [
      "Check how username and password inputs are concatenated into the SQL statement.",
      "SQL comment syntax '--' or '/*' can comment out the rest of the query."
    ]
  }
]
```

## 6. Detailed App Specifications

### App 1: `apps/blog-sqli` (Port 8001)
- **Tech Stack**: Flask, SQLite, Jinja2.
- **Vulnerabilities**:
  1. `blog-sqli-login` (SQLi Login Bypass) - Easy / Medium / Hard
  2. `blog-sqli-union` (UNION-based Extraction) - Easy / Medium / Hard
  3. `blog-sqli-xss` (Stored XSS in Comments) - Easy / Medium / Hard

### App 2: `apps/notes-idor` (Port 8002)
- **Tech Stack**: Express.js, PostgreSQL 16.
- **Vulnerabilities**:
  1. `notes-idor-view` (IDOR Note Access) - Easy / Medium / Hard
  2. `notes-idor-admin` (Broken Access Control User -> Admin) - Easy / Medium / Hard

### App 3: `apps/file-share` (Port 8003)
- **Tech Stack**: FastAPI, Uvicorn, Python 3.12.
- **Vulnerabilities**:
  1. `file-share-traversal` (Path Traversal in download/preview) - Easy / Medium / Hard
  2. `file-share-upload` (Unrestricted File Upload) - Easy / Medium / Hard
  3. `file-share-mime` (Weak MIME Validation) - Easy / Medium / Hard

### App 4: `apps/shop-auth` (Port 8004)
- **Tech Stack**: Node.js 20, Express.
- **Vulnerabilities**:
  1. `shop-auth-jwt` (Weak JWT / Alg None / Weak Secret) - Easy / Medium / Hard
  2. `shop-auth-bruteforce` (No Login Rate Limiting / Header Bypass) - Easy / Medium / Hard
  3. `shop-auth-reset` (Predictable Password Reset Token) - Easy / Medium / Hard

### App 5: `apps/ping-tool` (Port 8005)
- **Tech Stack**: Flask, Python 3.12.
- **Vulnerabilities**:
  1. `ping-tool-rce` (Command Injection in Ping Tool) - Easy / Medium / Hard
  2. `ping-tool-ssrf` (SSRF in HTTP Health/Status Checker) - Easy / Medium / Hard
  3. `ping-tool-xss` (Reflected XSS in Host/Error Output) - Easy / Medium / Hard

## 7. Scoreboard Specification (`scoreboard/`, Port 8000)
- **UI Pages**:
  - Challenge Board: Filter by app, difficulty, OWASP category. Submit flag modal/form.
  - Progressive Hints: Costs 25% of points per hint revealed.
  - Leaderboard: User rankings, total score, solves, timestamps, first-blood badges.
  - Admin Reset: API and web form to reset leaderboard scores (protected by admin key or local-only).
- **Security & Integrity**:
  - Flags stored as HMAC-SHA256 (`HMAC-SHA256(SCOREBOARD_SECRET, flag)`).
  - Rate-limiting on submissions (e.g. max 5 attempts per 10s per player).
  - Duplicate submissions rejected.

## 8. Safety & Container Hardening
- Base images pinned to specific version tags (`python:3.12-slim`, `node:20-alpine`, `postgres:16-alpine`).
- Non-root users inside containers (`RUN useradd -m ...` or `USER node` / `USER 1000:1000`) where feasible.
- Read-only root filesystems where appropriate, writable temp/uploads mounted as volumes.
- CPU & memory resource limits in `docker-compose.yml` (`cpus: '0.50'`, `memory: 256M`).
- No privileged mode, no host volume mounts of sensitive directories, no `docker.sock`.

## 9. Deliverables Checklists
Every app folder must include:
- `Dockerfile` with healthcheck
- `src/` application code and seed database scripts
- `README.md` (overview, port, categories)
- `WALKTHROUGH.md` (Hints, Collapsible Solutions without literal flags, How to Fix)
- `challenges.json` (aligned with schema)
